# 用户隐私权利请求履约工作台

覆盖访问、更正、删除、撤回同意和限制处理请求的多页面履约工作台。项目使用 Next.js App Router、Chakra UI、Zustand、TanStack Query、tRPC、Zod 和 TypeScript 构建。

## 功能

- 客服登记请求，按登记时冻结的地区期限模板生成处理步骤；之后模板改版只影响新登记请求，旧请求沿用快照期限与原到期日。
- 处理动作绑定当前工作区版本（乐观并发）：跨标签页/多系统协同时，先保存的版本生效，基于旧版本的整包提交在客户端与服务端双重拒绝，避免覆盖他人刚完成的任务与审计。
- 每个涉及系统独立登记处理回执（幂等键）：首次接受才生成一份回执证据；超时重发按同一笔认，只追加重发尝试，不重复生成证据。
- 跨系统回执全部到齐且无未复核冲突后才能合并结果；未合并不能关闭。
- 冲突为结构化记录，必须逐项记录复核人、复核时间与结论；存在未复核冲突时服务端拒绝合并与关闭。
- 身份材料只保存掩码引用和摘要，不保存材料明文；核验动作记录核验人与时间。
- 重复请求、身份材料不足、跨系统结果冲突自动进入复核队列。
- 支持任务开始、完成和阻断，冲突逐项复核，延期必须填写原因。
- 截止时间前关闭必须记录提前关闭理由，回执未齐、未合并或存在未复核冲突时服务端拒绝关闭。
- 无版本号的旧浏览器数据首次打开自动迁移：补齐冻结模板快照（沿用原到期日）、身份核验记录、已完成任务回执与结构化冲突，不改动任何业务时间点。
- 页面可见每份回执是首次接受还是超时重发、请求当前卡在哪个系统，以及结果合并记录。
- 汇总登记、核验、分派、回执、证据、合并、冲突、延期和关闭审计，导出含冻结模板与回执记录的脱敏处理包。

tRPC 路由使用 Zod 校验操作输入（含 `expectedRevision` 版本守卫）；TanStack Query 管理服务数据并通过 `storage` 事件跨标签页同步；Zustand 管理工作区筛选状态；每次成功操作都会把完整工作区写入浏览器 `localStorage`。旧数据由 `src/services/migration.ts` 在加载时迁移并回写。

## 运行

```bash
npm install
npm run dev
```

开发服务地址：`http://localhost:18457`

## 构建

```bash
npm run build
npm run start
```

## 目录

```text
src/
  app/          Next App Router 页面与 tRPC API Handler
  components/   应用外壳、页面头、状态标签
  features/     总览、请求列表、请求详情、复核、系统、审计
  lib/          Zod Schema、tRPC 客户端、TanStack Query Hooks、本地存储
  server/       tRPC 服务路由
  services/     流程模板和履约业务规则
  stores/       Zustand 工作区状态
  types/        领域类型
```
