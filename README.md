# 用户隐私权利请求履约工作台

覆盖访问、更正、删除、撤回同意和限制处理请求的多页面履约工作台。项目使用 Next.js App Router、Chakra UI、Zustand、TanStack Query、tRPC、Zod 和 TypeScript 构建。

## 功能

- 客服登记请求，根据地区、身份核验状态和请求类型生成处理步骤与期限。
- 处理动作绑定请求当前版本（乐观锁）：旧页面基于过期版本的整包保存会被服务端拒绝并提示刷新，不会覆盖其他系统刚完成的任务与审计；多标签页通过 storage 事件自动同步最新版本。
- 定位相关系统、分派任务、登记执行证据、合并跨系统结果并记录处理意见。
- 跨系统回执按“系统 + 回执编号”幂等登记：首次接受生成唯一回执证据并推进该系统任务；超时重发只追加送达留痕，不重复生成证据、不重复推进任务。失败回执自动进入冲突复核并阻断对应系统。
- 跨系统回执全部接受后才激活结果合并；回执未到齐、任务未完成或冲突未复核时服务端拒绝关闭。
- 期限按请求登记时的地区模板冻结（模板版本与天数快照在请求上），之后调整模板只影响新登记的请求；地区/类型/涉及系统登记后不可在编辑中改写。
- 旧浏览器无版本号数据首次打开自动迁移：补齐工作区/请求版本号、冻结模板快照和缺失的身份核验记录，沿用原到期日（含已登记延期）不重新起算，迁移动作进入审计且幂等。
- 身份材料只保存掩码引用和摘要，不保存材料明文。
- 重复请求、身份材料不足、跨系统结果冲突自动进入复核队列。
- 支持任务开始、完成和阻断，冲突逐项复核，延期必须填写原因。
- 截止时间前关闭必须记录提前关闭理由，未完成任务、回执未齐或存在冲突时服务端拒绝关闭。
- 页面可见每个系统回执的接受/失败/等待/重发次数与留痕、请求当前卡在哪个系统，证据标注来源（回执接受生成/人工登记/旧数据补齐）。
- 汇总登记、核验、分派、证据、回执、冲突、延期和关闭审计，导出脱敏处理包。

tRPC 路由使用 Zod 校验操作输入（所有请求级动作必须携带 `expectedVersion`）；TanStack Query 管理服务数据；Zustand 管理工作区筛选状态；每次成功操作都会把带 `schemaVersion` 的完整工作区写入浏览器 `localStorage`。

## 运行

```bash
npm install
npm run dev
```

开发服务地址：`http://localhost:18457`

## 构建

```bash
npm run build
npm run start
```

## 目录

```text
src/
  app/          Next App Router 页面与 tRPC API Handler
  components/   应用外壳、页面头、状态标签
  features/     总览、请求列表、请求详情、复核、系统、审计
  lib/          Zod Schema、tRPC 客户端、TanStack Query Hooks、本地存储
  server/       tRPC 服务路由
  services/     流程模板和履约业务规则
  stores/       Zustand 工作区状态
  types/        领域类型
```
